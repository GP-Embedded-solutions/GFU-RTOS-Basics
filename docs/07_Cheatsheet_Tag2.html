Die drei Ebenen — und wann sie wirken
Build (.config) → nach Kernel-Neubau · Boot (cmdline.txt) → nach Neustart · Laufzeit (chrt, taskset, sysfs) → sofort.
Build entscheidet, was möglich ist. Boot, was reserviert ist. Laufzeit, wer es bekommt.

cyclictest — die wichtigsten Flags

-mSpeicher sperren (mlockall)
-SSMP-Modus: ein Thread je Kern
-p 99Priorität der Messthreads
-i 1000Basisintervall in µs
-D 60sMessdauer (mind. 60 s!)
-h 200Histogramm bis 200 µs
-a 3nur auf Kern 3 messen
-qstill, nur Endergebnis

Standardlauf

sudo cyclictest -m -S -p 99 -i 1000 -D 60s -h 200
Nur Max zählt. Der Mittelwert beschreibt ein System, das es nicht gibt. Und: nie ohne Last messen.

rtla — wer stiehlt die Zeit?

Boot-Parameter (cmdline.txt / GRUB)

isolcpus=3Scheduler meidet Kern 3
nohz_full=3kein Timer-Tick auf Kern 3
rcu_nocbs=3RCU-Callbacks woanders
irqaffinity=0,1IRQs nur auf Kern 0 und 1
threadirqsIRQ-Handler als Threads
processor.max_cstate=1tiefe Schlafzustände aus (x86)
Raspberry Pi: cmdline.txt muss eine einzige Zeile sein. Ein Zeilenumbruch, und alles danach wird stillschweigend ignoriert. Wirksam erst nach Neustart.

Isolierung nachweisen — vier Fragen

1. Steht es in der Bootzeile?cat /proc/cmdline
2. Sieht der Kernel es so?cat /sys/devices/system/cpu/isolated
3. Läuft dort noch etwas?ps -eLo pid,psr,comm | awk '$2==3'
4. Interrupts dort?cat /proc/interrupts (2× messen, Differenz)
Drei von vier ist nicht isoliert.

Scheduling, Prioritäten & Mutexe

Tag 2 · Seite 2

Scheduling-Policies

SCHED_OTHER (CFS)fair, kein Vorrang — Standard
SCHED_FIFOläuft bis blockiert/verdrängt, keine Zeitscheibe
SCHED_RRwie FIFO + Zeitscheibe unter Gleichrangigen
SCHED_DEADLINEFrist + Rechenbedarf statt Wichtigkeit
SCHED_IDLEnur wenn sonst nichts will

Prioritätsschema

99Kernel-Threads, Watchdog — Finger weg
80–90harte Deadline, kurze Laufzeit
50–79Echtzeit mit Toleranz
10–49echtzeitnah, unkritisch
SCHED_OTHERalles Übrige
Priorität ist eine Aussage über Deadlines, kein Wunsch.

Governor & Energie

cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
Determinismus und Energieeffizienz sind ein Zielkonflikt. Vor jeder Messung: Governor auf performance.

IRQ-Affinität

cat /proc/interrupts
echo 3 | sudo tee /proc/irq/<N>/smp_affinity  # Bitmaske: 3 = Kern 0+1
Maske ist hexadezimal und bitweise: 1=Kern 0, 2=Kern 1, 3=Kern 0+1, 8=Kern 3. Manche IRQs lassen sich nicht verschieben.

Mutexe & Prioritätsinversion

pthread_mutexattr_init(&a);
pthread_mutexattr_setprotocol(&a,
    PTHREAD_PRIO_INHERIT);
pthread_mutex_init(&m, &a);
beschränkte InversionWartezeit = kritischer Abschnitt. Planbar.
unbeschränkte InversionDritter Thread verdrängt den Halter. Nicht abschätzbar.
PRIO_INHERITHalter erbt Priorität des Wartenden
PRIO_PROTECTCeiling: feste Obergrenze am Mutex
Beste Lösung bleibt: kein Mutex zwischen Prioritätsklassen teilen. Vererbung ist eine Reparatur.

Speicher

#include <sys/mman.h>
mlockall(MCL_CURRENT | MCL_FUTURE);
Regel wichtiger als der Syscall: in der Echtzeitschleife wird nicht mehr alloziert. Speicher in der Startphase holen und anfassen.

Zyklus ohne Drift

clock_gettime(CLOCK_MONOTONIC, &t);
while (1) {
  t.tv_nsec += 1000000; normalize(&t);
  clock_nanosleep(CLOCK_MONOTONIC,
    TIMER_ABSTIME, &t, NULL);
  arbeit();
}
sleep() und relatives nanosleep() driften: die Arbeitszeit addiert sich auf. Immer absolut.
